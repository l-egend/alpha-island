Alpha Island 人格提示词编写规范

一、用途
人格提示词只描述角色、语气、表达习惯和对用户的称呼。桌面工具、状态读取、权限及如实反馈规则由程序内置，用户无需重复编写系统提示词。

二、推荐结构
1. 角色：例如“温和、可靠的桌面助理”。
2. 称呼：希望助手怎样称呼你。
3. 语气：简洁、自然、正式或活泼；是否使用表情。
4. 回答习惯：先给结论、必要时列步骤、不确定时直说。
5. 边界：不要编造设备读数、操作结果、对话记忆或没有发生的事情。

示例：
你叫小岛，是一位温和、可靠的桌面助理。默认称呼我为“你”。
使用自然简洁的中文，先给结论，再按需补充步骤。
少用表情，不连续追问。不确定时坦诚说明。

三、文件与导入
使用 .txt 纯文本，推荐 UTF-8；也支持带 BOM 的 Unicode 文本和常见 GBK 文本。
单个文件最多 64 KB，正文最多 8000 字符；推荐 200～1000 字符。
点击“导入 TXT”后，外部文件会复制到本文件夹，原文件不会被修改。
可在本文件夹保存多个角色，每次重新导入想使用的文件即可切换。
在设置文本框内继续编辑，会修改当前人格设置，不会覆盖导入的原始文件；修改文件后需要重新导入才会生效。
清空人格文本后使用默认桌面助理。旧版自定义系统提示词会作为人格偏好保留。
本规范和示例只会在缺少时创建，不会覆盖你修改过的文件。

四、token 与状态读取
人格仅在会话首次被接口接受的请求中发送一次，后续提问和工具续接不会再附加。HTTP 错误或连接失败前未被接受时可重试；打开历史会话或重启不会重复附加。修改人格后请新建或清空会话。普通无状态 API 后续只参考聊天历史，无法保证完整记住人格设定。内置系统规则、当轮工具说明及聊天历史仍随请求发送并计入 token；首次人格也计入输入 token。
岛内状态不会自动附加，也不会把旧状态包随历史反复发送。模型需要时才调用对应分区的读取工具；工具结果也会产生 token，仅在当前任务的调用过程中提供。
不要把电量、系统指标、天气、通知列表等实时数据写死在人格里；需要时由助手调用工具查询。
不要写入真实 API Key、密码、银行卡、身份证或私人资料。
人格设定不能改变工具权限，不能让助手假装读取成功或执行成功。
